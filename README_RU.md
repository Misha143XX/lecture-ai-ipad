# Lecture AI iPad 0.3.1 — проверка обхода GPU-ограничения

У друга iPad Pro 11″ с iPadOS 18.4.1. В Safari WebGPU доступен, но WebLLM требует 32768 Б памяти на вычислительную группу при лимите устройства 16384 Б. Переключатели Safari это ограничение не изменяют.

## Обновление

1. Распаковать ZIP.
2. GitHub → `lecture-ai-ipad` → Add file → Upload files → загрузить **содержимое** папки в корень репозитория.
3. Commit changes. Дождаться успешной публикации GitHub Pages.
4. Друг открывает приложение в Safari и проверяет метку `iPad · Preview 0.3.1`. Не удалять PWA и не очищать браузерные данные.
5. Открыть существующую лекцию → «Конспект» → «Создать связный ИИ-конспект (бета)». На iPad с GPU-лимитом 16384 появится статус **CPU-режим**.
6. **Это только экспериментальная проверка:** CPU делает частичный конспект первых двух фрагментов, а не всю 15-минутную лекцию. Если успешно, дальнейшая задача — обработка всей записи с управлением памятью и временем.

## Ограничения

- CPU-модель в формате ONNX q4 скачивается бесплатно (сотни МБ) и работает без WebGPU. Модель и библиотека загружаются из Hugging Face/CDN; видео и текст не отправляются на сервер для распознавания или генерации.
- Safari может завершить обработку из-за нехватки оперативной памяти. Результат не проверен на реальном iPad.
- Не запускайте распознавание Whisper и конспектирование одновременно.
- Проверяйте ошибочные имена/даты с оригиналом; небольшая модель не гарантирует точности и может выдумывать сведения.
- Важные видео и расшифровки экспортируйте отдельно: браузерное хранилище может очищаться системой.
- FIN2 и Mac-версия Lecture AI не затрагиваются.
